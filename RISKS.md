## Stop-ship conditions

Do not distribute a build outside the development team when any of these is true:

- a known High/Critical trust-boundary bypass is open;
- localhost/LAN favicon fetching or automatic external-scheme launch is reproducible;
- `<all_urls>` is granted on install, cannot be revoked, or content scripts ignore the effective grant;
- private tabs persist browser/extension state other than the explicitly disclosed downloaded file;
- unknown-length downloads can exceed the byte/disk policy or leave tracked partial files;
- a malformed package/store record can crash startup or execute after integrity failure;
- private-API/ad-SDK scans fail;
- macOS build/tests are red or have not run for the candidate commit;
- signing/profile identity does not match the shipped app;
- required device checks for file protection, VoiceOver, memory, and WebKit behavior lack evidence.

## Accepted product limitations

- Extension packages are local and unsigned. Publisher verification and automatic updates are absent.
- Authorized content scripts can read/change matching DOM; `WKContentWorld` isolates globals, not DOM.
- Extension permissions are all-or-nothing per extension. There is no per-site grant, no revoke UI, and no
  install flow at all; only the app's own bundled harness is trusted.
- Extension popups, options pages and `webkit-extension://` navigation are unimplemented rather than
  restricted: the app does not yet use `WKWebExtensionContext.webViewConfiguration`, which Apple requires
  for any web view that navigates to an extension URL.
- Failed `WKDownload` resume data is intentionally discarded; resumable download UI is not implemented.
- MV3 `background.service_worker` loads without error and never runs (measured, R-18). Native messaging and
  long-lived ports are answered as unavailable by the host delegate. Whether `declarativeNetRequest` and
  `webRequest` actually enforce anything is unmeasured — the harness only reports the APIs as present, which
  is not evidence (DECISIONS §4.2.5). M3 closes this with an internal test server.
- A private download file persists because the user explicitly saves it; the UI warns before starting and
  metadata does not preserve its private source URL.
- There is no extension repository. Extensions are loaded from a `resourceBaseURL` handed straight to
  `WKWebExtension`, and WebKit reads resources from that tree itself, so the app cannot interpose an
  integrity recheck between a scan and a read. `ExtensionIdentity` can still hash a tree on demand; nothing
  calls it yet. Re-establishing tamper detection is M4 work, tied to the install path.
